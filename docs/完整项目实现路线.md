## 一、MQTT服务器部署方案

### 1.1 方案对比

| 方案 | 部署位置 | 优点 | 缺点 | 推荐度 |
|------|----------|------|------|--------|
| **方案A：公共Broker** | 云端（broker.emqx.io） | 零成本、零配置、立即可用 | 不稳定、数据公开、延迟高 | ⭐⭐ 仅测试用 |
| **方案B：电脑部署** | 你的Windows电脑 | 免费、稳定、局域网低延迟 | 电脑必须常开 | ⭐⭐⭐⭐ 开发调试推荐 |
| **方案C：ESP32部署** | ESP32开发板 | 独立运行、不依赖电脑 | 性能差、配置复杂、不稳定 | ⭐ 不推荐 |
| **方案D：路由器部署** | OpenWrt路由器 | 24小时运行、零额外硬件 | 需要刷OpenWrt | ⭐⭐⭐⭐⭐ 生产推荐 |

### 1.2 推荐方案：电脑部署EMQX（开发阶段）

#### 步骤1：下载EMQX
1. 访问 https://www.emqx.io/zh/downloads
2. 选择 **EMQX Broker** → **Windows** → 下载 `.zip` 文件
3. 解压到 `C:\emqx`

#### 步骤2：启动EMQX
```powershell
cd C:\emqx\bin
.\emqx.cmd console
```
看到 `EMQX Broker is running now.` 表示成功。

#### 步骤3：访问Dashboard
浏览器打开：`http://localhost:18083`
- 用户名：`admin`
- 密码：`public`

#### 步骤4：修改代码中的Broker地址
在所有设备的代码中，将Broker地址改为你的电脑IP：

```c
// 找到 mqtt_iot_protocol.h 或各设备的MQTT配置
#define MQTT_BROKER_URI "mqtt://192.168.1.100"  // 改为你的电脑局域网IP
```

查看电脑IP：
```powershell
ipconfig
# 找到 "无线局域网适配器 WLAN" 下的 IPv4 地址
```

### 1.3 为什么不推荐ESP32部署MQTT Broker？

1. **内存不足**：ESP32只有520KB RAM，MQTT Broker至少需要2MB
2. **性能差**：ESP32主频240MHz，处理多设备连接会卡顿
3. **无现成方案**：ESP-IDF没有官方MQTT Broker库，需要第三方移植
4. **稳定性差**：ESP32作为Broker，一旦死机所有设备断连

**结论**：ESP32只适合作为MQTT Client（发布者/订阅者），不适合做Broker。

## 二、GPIO调试指南

### 2.1 调试工具准备

| 工具 | 用途 | 价格 |
|------|------|------|
| 万用表 | 测量GPIO电平（0V=低，3.3V=高） | 必备 |
| 逻辑分析仪（可选） | 捕获PWM波形、UART数据 | 30元（Saleae克隆） |
| LED+220Ω电阻 | 测试GPIO输出 | 2元 |
| 杜邦线 | 连接测试 | 5元 |

### 2.2 灯光GPIO调试（以一楼GPIO2为例）

#### 方法1：串口命令调试
```bash
# 烧录固件后，打开串口监视器
idf.py -p COM3 monitor

# 在控制台输入（如果实现了console）
gpio set 2 1    # 点亮
gpio set 2 0    # 熄灭
```

#### 方法2：MQTT命令调试
使用MQTT客户端工具（如MQTTX）：
1. 连接到Broker
2. 发布到 `xiaozhi/iot/cmd/1`
3. Payload（十六进制）：`01 01 00 01 00 00 00 00`
   - `01` = IOT_CMD_SET_GPIO
   - `01` = device_id
   - `00` = gpio_index 0（灯光1）
   - `01` = value 1（开）

#### 方法3：代码硬编码调试
在 `iot_control_task.c` 的 `Device_Refresh_Task` 中临时添加：
```c
// 临时测试代码，调试完删除
static int test_count = 0;
if (test_count++ % 100 == 0) {
    HW_Gpio_Write(2, 1);  // 点亮
    vTaskDelay(pdMS_TO_TICKS(1000));
    HW_Gpio_Write(2, 0);  // 熄灭
}
```

### 2.3 舵机GPIO调试（以一楼GPIO18为例）

#### 步骤1：验证PWM输出
```c
// 在代码中添加测试
HW_Servo_Set_Angle(LEDC_CHANNEL_0, 0);    // 0度
vTaskDelay(pdMS_TO_TICKS(2000));
HW_Servo_Set_Angle(LEDC_CHANNEL_0, 90);   // 90度
vTaskDelay(pdMS_TO_TICS(2000));
HW_Servo_Set_Angle(LEDC_CHANNEL_0, 180);  // 180度
```

#### 步骤2：用逻辑分析仪验证
- 通道接GPIO18
- 预期波形：50Hz（周期20ms），高电平0.5ms~2.5ms
- 0度 = 0.5ms高电平
- 90度 = 1.5ms高电平
- 180度 = 2.5ms高电平

#### 步骤3：常见问题排查
| 现象 | 原因 | 解决 |
|------|------|------|
| 舵机不动 | 供电不足 | 舵机需要5V，ESP32的3.3V可能不够 |
| 舵机抖动 | PWM频率不对 | 检查LEDC配置，必须是50Hz |
| 舵机角度不对 | 脉宽计算错误 | 检查 `pulse_width` 计算公式 |

### 2.4 继电器GPIO调试

继电器通常是**低电平触发**或**高电平触发**，需要先确认：
```c
// 测试代码
HW_Gpio_Write(6, 1);  // 高电平
vTaskDelay(pdMS_TO_TICKICS(1000));
HW_Gpio_Write(6, 0);  // 低电平
// 听继电器是否有"咔嗒"声
```

## 三、ESP32-P4融入MQTT控制IoT设备路线

### 3.1 P4硬件架构理解

```
ESP32-P4-Function-EV-Board
├── P4主芯片（无WiFi/蓝牙）
└── 板载ESP32-C6（通过ESP-Hosted提供WiFi）
```

**关键限制**：
- P4不能直接使用ESP-NOW（ESP-Hosted不转发ESP-NOW控制接口）
- P4只能通过ESP-Hosted使用标准TCP/IP（WiFi）
- **因此P4必须使用MQTT**，与现有架构完美兼容

### 3.2 P4集成步骤

#### 阶段1：P4作为MQTT Client（1-2周）

**目标**：P4能连接MQTT Broker，订阅/发布Topic

**步骤**：
1. 在 `lvgl_prj` 项目中添加MQTT依赖
   ```cmake
   # lvgl_prj/main/CMakeLists.txt
   set(COMPONENT_REQUIRES
       mqtt
       # ... 其他依赖
   )
   ```

2. 创建 `mqtt_p4_client.c`
   ```c
   // 复用 shared/mqtt_iot_protocol.h 中的Topic定义
   // P4订阅：xiaozhi/iot/cmd/broadcast, xiaozhi/iot/cmd/4
   // P4发布：xiaozhi/iot/resp/{mac}, xiaozhi/iot/heartbeat/{mac}
   ```

3. P4的device_id设为4，Client ID设为 `xiaozhi_p4_panel`

4. P4收到命令后，通过LVGL界面显示设备状态

#### 阶段2：P4作为控制面板（2-3周）

**目标**：P4触摸屏可以控制所有IoT设备

**步骤**：
1. LVGL界面设计：
   - 一楼/二楼/三楼设备列表
   - 每个设备有开关按钮
   - 场景按钮（回家/睡眠/起床）

2. 触摸事件 → MQTT发布：
   ```c
   // 用户点击"打开一楼客厅灯"
   iot_command_packet_t cmd = {
       .command = IOT_CMD_SET_LIGHT,
       .device_id = 1,
       .gpio_index = 1,  // 客厅灯
       .value = 1
   };
   esp_mqtt_client_publish(client, "xiaozhi/iot/cmd/1", &cmd, sizeof(cmd), 1, 0);
   ```

3. 订阅响应Topic，更新UI状态：
   ```c
   // 收到一楼从机响应
   // 更新LVGL按钮状态为"已开启"
   ```

#### 阶段3：P4与主机协同（1周）

**目标**：P4和主机（S3）可以互相接管控制

**方案**：
- 主机和P4订阅相同的Topic
- 两者都可以发布命令
- 通过MQTT实现状态同步

### 3.3 P4代码架构

```
lvgl_prj/
├── main/
│   ├── mqtt_p4_client.c      # MQTT连接、订阅、发布
│   ├── p4_ui_controller.c    # LVGL界面与MQTT桥接
│   ├── p4_device_panel.c     # 设备控制面板UI
│   └── p4_scene_panel.c      # 场景控制面板UI
└── components/
    └── shared/               # 复用 shared/mqtt_iot_protocol.h
```

## 六、项目客观见解

### 6.1 技术优势

1. **架构清晰**：混合分层架构（BSP+APP）职责分明，易于维护
2. **Flag-driven设计**：标志位驱动避免了状态不同步问题
3. **MQTT重构正确**：ESP-NOW→MQTT是必然选择，P4集成需要MQTT
4. **设备自动发现**：ANNOUNCE机制避免了MAC硬编码

### 6.2 潜在风险

1. **公共Broker不稳定**：`broker.emqx.io` 可能随时不可用，必须自建
2. **WiFi依赖**：所有设备必须同一WiFi，断网则全瘫
3. **P4集成复杂度**：LVGL+MQTT+ESP-Hosted组合调试难度大
4. **舵机供电**：多个舵机同时动作可能拉低ESP32电压

### 6.3 建议优先级

| 优先级 | 任务 | 原因 |
|--------|------|------|
| P0 | 自建MQTT Broker | 公共Broker不可靠 |
| P0 | 完成3个从机MQTT调试 | 核心功能 |
| P1 | 主机MCP适配MQTT | 语音控制入口 |
| P1 | P4基础MQTT集成 | 面板控制 |
| P2 | P4 LVGL完整面板 | 用户体验 |
| P2 | 断线重连优化 | 稳定性 |
| P3 | OTA升级 | 后期维护 |
| P3 | MQTT加密（TLS） | 安全性 |

### 6.4 一个月目标建议

**不要追求完美，追求可用**：
- ✅ 必须完成：3从机MQTT控制+主机语音控制
- ⚠️ 尽量完成：P4基础面板
- ❌ 可以放弃：P4完整UI、OTA、加密
