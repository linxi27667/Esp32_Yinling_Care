# 三楼从机 FreeRTOS 任务架构总结

## 项目背景

本项目为"银龄智享"智慧养老系统的三楼从机，采用ESP32-S3芯片，基于FreeRTOS实时操作系统构建分布式物联网节点。

**核心技术架构：**
- Flag-driven设备控制模型（枚举状态机）
- ESP-NOW低功耗无线通信协议
- MCP工具协议（自主开发）
- 一主机多从机分布式架构

## 完整任务清单

| 序号 | 任务名 | 所在文件 | 优先级 | 栈空间 | 周期 | 职责 | 类型 |
|:---:|--------|----------|:------:|-------:|------|------|:----:|
| 1 | `console_event_task` | app_uart.c | **10** | 8192 | 阻塞等输入 | 调试串口输入（AI对话） | 控制台 |
| 2 | `uart_event_task` | app_uart.c | **10** | 16384 | 事件触发 | UART0事件处理（AI语音） | 通信 |
| 3 | `Device_Refresh_Task` | iot_control_task.c | **3** | 4096 | 100ms | GPIO刷新（标志位→硬件） | 驱动 |
| 4 | `Sensor_ADC_Task` | sensor_adc_task.c | **4** | 4096 | 500ms | 烟雾+雨滴+求助检测 | 感知 |
| 5 | `Heartbeat_Task` | esp_now_heartbeat.c | **5** | 3072 | 30s | 心跳包保活 | 通信 |
| - | `EspNow_Recv_Callback` | esp_now_receive.c | **中断** | - | 事件触发 | ESP-NOW接收解析 | 通信 |
| - | `EspNow_Send_Callback` | esp_now_receive.c | **中断** | - | 事件触发 | ESP-NOW发送回调 | 通信 |

## ESP-NOW 任务分层架构

```
┌─────────────────────────────────────────────────────────────────────┐
│                        ESP-NOW 通信分层模型                          │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  Layer 1: 中断层 (最高实时性)                                        │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  EspNow_Recv_Callback    │  EspNow_Send_Callback            │   │
│  │  - 数据接收立即触发       │  - 发送完成回调                   │   │
│  │  - 更新全局标志位         │  - 记录发送状态                    │   │
│  │  - 不可调用阻塞API        │  - 不可调用阻塞API                │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                              ↓                                      │
│  Layer 2: 应用层 (高优先级)                                          │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  Device_Refresh_Task (Priority 3)                           │   │
│  │  - 100ms周期刷新GPIO                                         │   │
│  │  - 读取标志位 → 控制硬件                                      │   │
│  │  - **这是最影响用户体验的任务**                                │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                              ↓                                      │
│  Layer 3: 感知层 (中等优先级)                                        │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  Sensor_ADC_Task (Priority 4)                               │   │
│  │  - 500ms周期采样ADC                                          │   │
│  │  - 烟雾/雨滴/求助检测                                        │   │
│  │  - 更新安全相关标志位                                          │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                              ↓                                      │
│  Layer 4: 保活层 (低优先级)                                          │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  Heartbeat_Task (Priority 5)                                │   │
│  │  - 30秒周期发送心跳                                           │   │
│  │  - 维护与主机连接状态                                          │   │
│  │  - **实时性要求最低**                                         │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

## 优先级分配原则

| 优先级 | 任务 | 分配理由 |
|:------:|------|----------|
| **中断** | ESP-NOW回调 | 硬件触发，最高实时性，不可阻塞 |
| **3** | Device_Refresh_Task | GPIO刷新直接影响设备响应，用户体验核心 |
| **4** | Sensor_ADC_Task | 安全检测（火灾/雨滴/求助），实时性中等 |
| **5** | Heartbeat_Task | 心跳30秒保活，实时性要求最低 |
| **10** | UART任务 | 调试/语音交互，人工响应，对实时性无要求 |

---

## 栈空间分配原则

| 任务 | 栈空间 | 分配理由 |
|------|:------:|----------|
| `Device_Refresh_Task` | 4096 | GPIO操作、循环打印，足够 |
| `Sensor_ADC_Task` | 4096 | ADC采样、阈值判断、UART发送，足够 |
| `Heartbeat_Task` | 3072 | ESP-NOW API调用需要更大栈（原2048不足） |
| `console_event_task` | 8192 | 控制台输入处理，字符串操作 |
| `uart_event_task` | 16384 | UART事件队列、cJSON解析、大量局部变量 |

## 新增功能：传感器与语音模块

### 硬件连接

```
天问ASR PRO模块 ──(UART1)──> ESP32（三楼从机）
                        │
烟雾传感器(MQ-2) ──(ADC1_CH0)──> ESP32
                        │
雨滴传感器 ──────(ADC1_CH3)──> ESP32
                        │
求助按键(GPIO48) ──────────────> ESP32
```

### 阈值配置（sensor_config.h）

```c
/* 烟雾传感器阈值 (mV) */
#define SMOKE_THRESHOLD_DRY        500    /* 清洁空气 */
#define SMOKE_THRESHOLD_LIGHT     1500   /* 轻度烟雾 */
#define SMOKE_THRESHOLD_FIRE      2500   /* 火灾警告 */

/* 雨滴传感器阈值 (mV) - 电压越低雨水越多 */
#define RAIN_THRESHOLD_DRY         3000   /* 干燥 */
#define RAIN_THRESHOLD_LIGHT_RAIN 2000   /* 小雨 */
#define RAIN_THRESHOLD_HEAVY_RAIN 1000   /* 大雨 */

/* 防抖计数 */
#define SMOKE_TRIGGER_COUNT        3
#define RAIN_TRIGGER_COUNT         2
```

### 天问ASR PRO指令枚举

```c
typedef enum {
    ASR_CMD_NONE = 0x00,
    ASR_CMD_FIRE_WARN = 0x01,    /* 火灾警报 */
    ASR_CMD_HELP_REQ = 0x02,      /* 求助报警 */
    ASR_CMD_LOW_BATTERY = 0x03,   /* 电量不足 */
    ASR_CMD_DOORBELL = 0x04       /* 门铃 */
} asr_command_enum_t;
```

### 雨天自动收衣服逻辑

```c
/* 在 Device_Refresh_Task 中 */
if (g_device_flags.rain_status != RAIN_STATUS_DRY) {
    /* 雨天且窗帘是开的，自动收起 */
    if (g_device_flags.servo[SERVO_1] != SERVO_180) {
        g_device_flags.servo[SERVO_1] = SERVO_180;
        ESP_LOGI(TAG, "[RAIN] Auto close curtain!");
    }
}
```

## 技术选型理由

| 组件 | 选型 | 理由 |
|------|------|------|
| 主控芯片 | ESP32-S3 | 双核240MHz，支持WiFi+蓝牙，AI推理能力强 |
| 通信协议 | ESP-NOW | 无需握手、低延迟、低功耗、无需路由器 |
| 架构模式 | Flag-driven | 通信与硬件解耦，状态一致性高 |
| 状态管理 | 枚举类型 | 可读性强、易扩展、安全性高 |

## 资源消耗估算

| 资源 | 使用量 | 可用量 | 使用率 |
|------|:------:|:------:|:------:|
| Flash | 约2MB | 4MB | 50% |
| RAM | 约180KB | 512KB | 35% |
| Task栈(最大) | 16384B (uart_event) | - | - |
| GPIO | 15个 | 40+个 | 37% |

## 架构优势

1. **实时性保障**：中断层保证ESP-NOW最高响应，Device_Refresh保证GPIO及时刷新
2. **状态一致性**：Flag-driven架构确保多源控制状态统一
3. **低功耗设计**：ESP-NOW + 太阳能供电，适合老年人使用场景
4. **可扩展性强**：新增功能只需添加枚举值和刷新逻辑，不影响现有架构
5. **代码模块化**：每个任务职责单一，易于维护和调试
