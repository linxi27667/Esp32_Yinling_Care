## 第一章：ESP32基础知识

### 1.1 芯片架构：双核Xtensa

小智使用的ESP32-S3芯片，是Espressif推出的双核微控制器，采用Xtensa LX7架构。

#### 双核分工

```
核心0（PRO CPU）        核心1（APP CPU）
     │                          │
     ├── WiFi驱动              ├── 用户应用
     ├── TCP/IP协议栈            ├── 小智AI
     ├── FreeRTOS调度器           ├── 显示驱动
     └── 硬件外设              └── 传感器读取
```

**核心0**：负责底层系统
- WiFi驱动（ESP-NOW、WiFi STA）
- TCP/IP协议栈
- FreeRTOS调度器
- 硬件外设（I2C、SPI、UART）

**核心1**：负责用户应用
- 小智AI推理
- MCP工具系统
- 显示驱动（OLED、LVGL）
- 音频处理
- 用户交互（按键、语音）

#### 内存架构

```
┌─────────────────────────────────────────────┐
│          内部SRAM (512KB)              │
├─────────────────────────────────────────────┤
│          外部PSRAM (8MB)              │
└─────────────────────────────────────────────┘
```

**内部SRAM**：存放关键代码、栈、FreeRTOS任务
**外部PSRAM**：存放大缓冲区（摄像头图像、音频数据、LVGL显存）

#### 代码示例：创建任务到指定核心

```c
// 在核心1上创建MPU6050读取任务
xTaskCreatePinnedToCore(
    Mpu6050Task,           // 任务函数
    "mpu6050_task",        // 任务名称
    4096,                   // 栈大小（4KB）
    NULL,                    // 参数
    5,                       // 优先级（1-24，5为中等）
    &mpu6050_task_handle_,  // 任务句柄
    1                        // 绑定到核心1
);
```

**为什么MPU6050任务绑定到核心1？**
- 核心0忙于WiFi和协议栈
- 核心1相对空闲，适合应用层任务
- 避免核心0被阻塞，影响网络通信

### 1.2 引脚分配

小智ESP32-S3-N8R8的引脚分配：

| 外设 | 引脚 | 说明 |
|------|------|------|
| **摄像头** | GPIO32-39 | DVP摄像头接口 |
| **麦克风** | GPIO41 | I2S数据输入（INMP441） |
| **扬声器** | GPIO40 | I2S数据输出（MAX98357） |
| **OLED** | GPIO15/14 | I2C总线（SDA/SCL） |

- OLED和MPU6050共用I2C总线（SDA: GPIO15, SCL: GPIO14）

## 第二章：FreeRTOS实时操作系统

### 2.1 FreeRTOS简介

FreeRTOS是小智项目使用的实时操作系统，负责任务调度、内存管理、同步机制。

#### 任务调度原理

```c
// FreeRTOS调度器的工作方式
while (1) {
    // 1. 查找最高优先级的就绪任务
    Task_t* task = FindHighestPriorityReadyTask();
    
    // 2. 切换上下文（保存寄存器、恢复寄存器）
    ContextSwitch(current_task, task);
    
    // 3. 任务运行一个时间片（1ms）
    task->run();
    
    // 4. 检查是否有更高优先级任务就绪
    if (HasHigherPriorityTask(task)) {
        ContextSwitch(task, current_task);
    }
}
```

**时间片**：每个任务最多运行1ms，然后调度器检查是否需要切换
**优先级**：数字越小优先级越高（0最高，24最低）

---

### 2.2 小智项目中的任务

| 任务名称 | 优先级 | 核心绑定 | 功能 |
|---------|---------|---------|------|
| `mpu6050_task` | 5 | 核心1 | 读取MPU6050传感器数据 |
| `audio_task` | 10 | 核心0 | 音频采集和处理 |
| `main_task` | 5 | 核心1 | 主事件循环 |
| `wifi_task` | 12 | 核心0 | WiFi驱动 |

**优先级设计原则**：
- 音频任务优先级高（10）：保证实时性，避免丢帧
- WiFi任务优先级最高（12）：保证网络通信稳定
- 应用层任务优先级中等（5）：不阻塞系统关键任务

---

### 2.3 事件组（EventGroup）

FreeRTOS的事件组是一种**任务间同步机制**，用于通知任务"某事发生了"。

#### 基本用法

```c
// 创建事件组
EventGroupHandle_t event_group = xEventGroupCreate();

// 设置事件位（通知其他任务）
xEventGroupSetBits(event_group, BIT0);  // 设置第0位

// 等待事件（阻塞当前任务）
EventBits_t bits = xEventGroupWaitBits(
    event_group,           // 事件组句柄
    BIT0 | BIT1,          // 等待第0位或第1位
    pdFALSE,               // 清除位（等待后是否清除）
    pdFALSE,               // 等待所有位（AND）或任意位（OR）
    portMAX_DELAY           // 永久等待
);

// 判断事件位
if (bits & BIT0) {
    // 第0位被设置了
}
```

#### 小智项目中的事件组应用

```c
// application.cc 中的事件组定义
event_group_ = xEventGroupCreate();

// 定义事件位
#define MAIN_EVENT_CLOCK_TICK          BIT0  // 时钟滴答（1秒一次）
#define MAIN_EVENT_WAKE_WORD_DETECTED  BIT1  // 唤醒词检测到
#define MAIN_EVENT_VAD_CHANGE          BIT2  // 语音活动检测变化
#define MAIN_EVENT_STATE_CHANGED       BIT3  // 设备状态变化
#define MAIN_EVENT_SEND_AUDIO         BIT4  // 音频队列可用
#define MAIN_EVENT_NETWORK_CONNECTED  BIT5  // WiFi连接成功
#define MAIN_EVENT_NETWORK_DISCONNECTED BIT6  // WiFi断开连接
```

#### 事件驱动编程流程

```
1. 底层驱动（WiFi、I2C）发生事件
   ↓
2. 通过事件组通知应用层
   xEventGroupSetBits(event_group_, MAIN_EVENT_NETWORK_CONNECTED);
   ↓
3. 应用层任务在xEventGroupWaitBits()中等待
   EventBits_t bits = xEventGroupWaitBits(event_group_, 
                                          MAIN_EVENT_NETWORK_CONNECTED, 
                                          pdFALSE, pdFALSE, portMAX_DELAY);
   ↓
4. 事件到来后，任务被唤醒处理
   if (bits & MAIN_EVENT_NETWORK_CONNECTED) {
       // 处理WiFi连接成功
   }
```

**优势**：
- 任务不需要轮询（节省CPU）
- 响应实时（事件发生立即唤醒任务）
- 代码解耦（驱动不关心谁在用事件）

### 2.4 实际案例：WiFi连接事件驱动

```c
// BSP层：WiFi事件回调（bsp_wifi.c）
static void event_handler(void* arg, esp_event_base_t event_base, 
                        int32_t event_id, void* event_data) {
    if (event_base == IP_EVENT && event_id == IP_EVENT_STA_GOT_IP) {
        // 获取到IP地址，设置事件组
        xEventGroupSetBits(s_wifi_event_group, WIFI_CONNECTED_BIT);
    }
}

// APP层：等待WiFi连接（bsp_wifi.c）
EventBits_t bits = xEventGroupWaitBits(
    s_wifi_event_group,
    WIFI_CONNECTED_BIT | WIFI_FAIL_BIT,
    pdFALSE, pdFALSE, portMAX_DELAY
);

if (bits & WIFI_CONNECTED_BIT) {
    ESP_LOGI(TAG, "连接成功");
    return true;
}
```

**流程**：
1. WiFi硬件获取IP
2. 事件回调函数设置`WIFI_CONNECTED_BIT`
3. `xEventGroupWaitBits()`返回
4. APP层处理连接成功

## 第三章：WiFi连接详解

### 3.1 WiFi驱动架构：三层设计

小智的WiFi驱动采用经典的**三层架构**：

```
┌─────────────────────────────────────────────┐
│         应用层（APP）                │
│  app_wifi.c                             │
│  - 存放SSID、密码                     │
│  - 调用BSP层接口                    │
├─────────────────────────────────────────────┤
│         硬件抽象层（BSP）              │
│  bsp_wifi.c                              │
│  - 封装ESP-IDF WiFi API                │
│  - 事件回调处理                        │
│  - 重试逻辑                            │
├─────────────────────────────────────────────┤
│         ESP-IDF驱动层                      │
│  esp_wifi.h / esp_event.h                │
│  - WiFi硬件驱动                         │
│  - 事件系统                            │
└─────────────────────────────────────────────┘
```

#### 应用层：app_wifi.c

**职责**：管理WiFi配置、触发连接

```c
// WiFi配置结构体
typedef struct {
    char ssid[32];      // 热点名称
    char password[64];  // 密码
    uint8_t max_retry;  // 最大重试次数
} bsp_wifi_config_t;

// 初始化WiFi并连接
void App_WiFi_System_Init(void) {
    bsp_wifi_config_t my_wifi_cfg = {
        .max_retry = 5,
        .ssid = "Ll",
        .password = "ljc12345"
    };
    
    // 调用BSP层开始连接
    if (BSP_WiFi_Init_And_Connect(&my_wifi_cfg)) {
        // 连接成功，打印图传地址
        printf("访问图传: http://192.168.1.100/stream\n");
    }
}
```

**关键点**：
- 应用层**不直接操作**WiFi硬件
- 通过BSP层接口调用（`BSP_WiFi_Init_And_Connect()`）
- 解耦：更换WiFi芯片只需修改BSP层

#### 硬件抽象层：bsp_wifi.c

**职责**：封装ESP-IDF API、处理事件、实现重试逻辑

```c
// WiFi事件组（用于通知连接结果）
static EventGroupHandle_t s_wifi_event_group;
#define WIFI_CONNECTED_BIT BIT0  // 连接成功
#define WIFI_FAIL_BIT      BIT1  // 连接失败

// ESP-IDF事件回调函数
static void event_handler(void* arg, esp_event_base_t event_base, 
                        int32_t event_id, void* event_data) {
    if (event_base == WIFI_EVENT && event_id == WIFI_EVENT_STA_START) {
        // WiFi启动成功，发起连接
        esp_wifi_connect();
    } 
    else if (event_base == WIFI_EVENT && event_id == WIFI_EVENT_STA_DISCONNECTED) {
        // WiFi断开连接，记录原因
        wifi_event_sta_disconnected_t* event = (wifi_event_sta_disconnected_t*) event_data;
        ESP_LOGE(TAG, "断开连接，原因: %d", event->reason);
        
        if (s_retry_num < s_max_retry) {
            // 重试连接
            esp_wifi_connect();
            s_retry_num++;
        } else {
            // 达到最大重试次数，设置失败标志
            xEventGroupSetBits(s_wifi_event_group, WIFI_FAIL_BIT);
        }
    } 
    else if (event_base == IP_EVENT && event_id == IP_EVENT_STA_GOT_IP) {
        // 获取到IP地址
        ip_event_got_ip_t* event = (ip_event_got_ip_t*) event_data;
        ESP_LOGI(TAG, "获取IP: " IPSTR, IP2STR(&event->ip_info.ip));
        xEventGroupSetBits(s_wifi_event_group, WIFI_CONNECTED_BIT);
    }
}
```

**事件驱动流程**：

```
WiFi硬件 → 事件发生 → event_handler() → 设置事件组 → App层等待 → 处理结果
```

### 3.2 核心连接逻辑：BSP_WiFi_Init_And_Connect()

```c
bool BSP_WiFi_Init_And_Connect(bsp_wifi_config_t *config) {
    // 步骤1：初始化NVS（WiFi校准数据存储）
    esp_err_t ret = nvs_flash_init();
    ESP_ERROR_CHECK(ret);
    
    // 步骤2：初始化网络接口
    ESP_ERROR_CHECK(esp_netif_init());
    ESP_ERROR_CHECK(esp_event_loop_create_default());
    esp_netif_create_default_wifi_sta();
    
    // 步骤3：初始化WiFi驱动
    wifi_init_config_t cfg = WIFI_INIT_CONFIG_DEFAULT();
    ESP_ERROR_CHECK(esp_wifi_init(&cfg));
    ESP_ERROR_CHECK(esp_wifi_set_mode(WIFI_MODE_STA));
    
    // 步骤4：注册事件监听器（关键！）
    esp_event_handler_instance_t instance_any_id;
    esp_event_handler_instance_t instance_got_ip;
    ESP_ERROR_CHECK(esp_event_handler_instance_register(
        WIFI_EVENT, ESP_EVENT_ANY_ID, &event_handler, NULL, &instance_any_id));
    ESP_ERROR_CHECK(esp_event_handler_instance_register(
        IP_EVENT, IP_EVENT_STA_GOT_IP, &event_handler, NULL, &instance_got_ip));
    
    // 步骤5：配置WiFi参数
    wifi_config_t wifi_config = {
        .sta = {
            .threshold.authmode = WIFI_AUTH_OPEN,  // 自动检测认证模式
        },
    };
    strncpy((char *)wifi_config.sta.ssid, config->ssid, 32);
    strncpy((char *)wifi_config.sta.password, config->password, 64);
    
    // 步骤6：启动WiFi
    ESP_ERROR_CHECK(esp_wifi_set_config(WIFI_IF_STA, &wifi_config));
    ESP_ERROR_CHECK(esp_wifi_start());
    
    // 步骤7：等待连接结果（死等事件组）
    EventBits_t bits = xEventGroupWaitBits(
        s_wifi_event_group,
        WIFI_CONNECTED_BIT | WIFI_FAIL_BIT,
        pdFALSE,
        pdFALSE,
        portMAX_DELAY
    );
    
    // 步骤8：判断结果
    if (bits & WIFI_CONNECTED_BIT) {
        ESP_LOGI(TAG, "连接成功: %s", config->ssid);
        return true;
    } else {
        ESP_LOGE(TAG, "连接失败: %s", config->ssid);
        return false;
    }
}
```

**关键点**：
- **NVS初始化**：WiFi驱动依赖NVS存储校准数据，必须先初始化
- **事件注册**：`esp_event_handler_instance_register()`将回调挂载到系统
- **阻塞等待**：`xEventGroupWaitBits()`死等，直到事件被设置
- **重试机制**：断开连接后自动重试，最多5次

### 3.3 NVS：非易失性存储

NVS（Non-Volatile Storage）是ESP32的Flash存储系统，用于保存配置数据。

#### 为什么WiFi需要NVS？

ESP32的WiFi模块需要存储**校准数据**（Calibration Data），包括：
- WiFi信道扫描结果
- 信号强度校准
- MAC地址缓存

**NVS初始化失败**会导致WiFi驱动报错！

```c
// 正确的NVS初始化流程
esp_err_t ret = nvs_flash_init();
if (ret == ESP_ERR_NVS_NO_FREE_PAGES || ret == ESP_ERR_NVS_NEW_VERSION_FOUND) {
    // Flash损坏或版本不兼容，擦除后重试
    ESP_ERROR_CHECK(nvs_flash_erase());
    ret = nvs_flash_init();
}
ESP_ERROR_CHECK(ret);
```

#### NVS存储结构

```
Flash分区布局：
┌─────────────────────────────────────────────┐
│  nvs (NVS存储)                      │
│  - WiFi配置                            │
│  - 用户设置                            │
│  - 设备信息                            │
├─────────────────────────────────────────────┤
│  phy_init (WiFi校准数据)               │
├─────────────────────────────────────────────┤
│  nvs_keys (NVS密钥管理)             │
└─────────────────────────────────────────────┘
```

4. **总耗时**：正常情况下3-5秒

## 第四章：ESP-NOW通信

### 4.1 ESP-NOW协议原理

ESP-NOW是Espressif推出的**无连接点对点通信协议**，基于WiFi硬件，但不需要TCP/IP协议栈。

#### 协议特性

| 特性 | 说明 |
|------|------|
| **无连接** | 不需要握手、连接状态管理 |
| **低延迟** | 直接MAC层通信，1-5ms响应 |
| **低功耗** | 不需要维持WiFi连接 |
| **简单** | 应用层自定义协议，灵活 |
| **广播** | 支持一对多通信（一个主机控制多个从机） |

#### 通信架构

```
主机（小智ESP32）              从机（其他ESP32）
     │                              │
     ├── ESP-NOW发送 ───────────────► ESP-NOW接收
     │                              │
     └── ESP-NOW接收 ◄─────────────── ESP-NOW发送
                                    │
                                    └── 执行GPIO操作
```

**ESP-NOW vs WiFi TCP**：

| 对比项 | ESP-NOW | WiFi TCP |
|---------|---------|----------|
| 延迟 | 1-5ms | 50-200ms |
| 复杂度 | 简单 | 中等 |
| 功耗 | 极低 | 中等 |
| 适用场景 | 局域控制 | 远程控制 |

---

### 4.2 自定义应用层协议

小智的ESP-NOW实现采用**自定义应用层协议**，数据包格式如下：

#### 命令类型定义

```c
typedef enum {
    IOT_CMD_SET_GPIO = 0x01,      // 设置GPIO状态
    IOT_CMD_GET_GPIO = 0x02,      // 读取GPIO状态
    IOT_CMD_GET_ALL_GPIO = 0x03, // 读取所有GPIO
    IOT_CMD_HEARTBEAT = 0x04,     // 心跳检测
    IOT_CMD_RESPONSE = 0x05,       // 响应答
    IOT_CMD_DISCOVER = 0x06,       // 设备发现
    IOT_CMD_ANNOUNCE = 0x07,       // 设备上线通知
    IOT_CMD_SET_SERVO = 0x10,     // 控制舵机
} iot_command_t;
```

#### 数据包格式

```c
typedef struct {
    uint8_t command;      // 命令类型（1字节）
    uint8_t device_id;    // 设备ID（1字节，1-4）
    uint8_t gpio_index;   // GPIO索引（1字节，0-7）
    uint8_t value;        // GPIO值（1字节，0或1）
    uint8_t reserved[4];  // 保留字段（4字节）
} iot_command_packet_t;
```

**数据包大小**：8字节（固定长度）

#### 协议设计原则

1. **固定长度**：所有命令都是8字节，简化解析
2. **设备ID**：支持最多4个从机（device_id: 1-4）
3. **GPIO索引**：每个从机最多8个GPIO（gpio_index: 0-7）
4. **响应机制**：从机收到命令后必须发送`IOT_CMD_RESPONSE`确认

### 4.5 ESP-NOW信道匹配（关键知识点）

#### 为什么信道必须匹配？

ESP-NOW基于WiFi硬件直接在MAC层通信，**两个设备必须在同一个WiFi信道才能通信**，即使连接到同一个路由器也不行！

#### WiFi信道分配机制

```
路由器（AP）
    │
    ├── 分配信道：Channel 11（固定或动态）
    │
    ├── 主机连接 → 跟随路由器信道 → Channel 11
    │
    └── 从机连接 → 跟随路由器信道 → Channel 11
```

**问题场景**：
```
主机代码：
    esp_now_peer_info_t peer = {
        .channel = 1,  // ❌ 固定信道1
        .ifidx = WIFI_IF_STA,
        .encrypt = false,
    };

从机代码：
    wifi_ap_record_t ap_info;
    esp_wifi_sta_get_ap_info(&ap_info);
    esp_now_peer_info_t peer = {
        .channel = ap_info.primary,  // ✅ 动态获取Channel 11
        .ifidx = WIFI_IF_STA,
        .encrypt = false,
    };

结果：主机在Channel 1，从机在Channel 11 → 无法通信！
```

#### 信道不匹配的后果

| 现象 | 原因 |
|------|------|
| 主机搜索不到从机 | 信道不同，ESP-NOW数据包无法到达 |
| 从机收不到命令 | 信道不同，无法接收数据 |
| 信号强度为0 | 不同信道，RSSI无法测量 |

#### 解决方案：动态获取WiFi信道

**主机端代码（正确做法）**：
```c
static bool HW_EspNow_Init(void) {
    esp_err_t ret = esp_now_init();
    if (ret != ESP_OK) {
        ESP_LOGE(TAG, "ESP-NOW init failed: %s", esp_err_to_name(ret));
        return false;
    }
    
    esp_now_register_recv_cb(HW_EspNow_Recv_Callback);
    
    // ✅ 动态获取WiFi信道
    wifi_ap_record_t ap_info;
    ret = esp_wifi_sta_get_ap_info(&ap_info);
    if (ret == ESP_OK) {
        ESP_LOGI(TAG, "Connected to AP: %s, Channel: %d", ap_info.ssid, ap_info.primary);
        
        esp_now_peer_info_t peer = {
            .channel = ap_info.primary,  // 使用路由器信道
            .ifidx = WIFI_IF_STA,
            .encrypt = false,
        };
        memcpy(peer.peer_addr, (uint8_t[]){0xFF, 0xFF, 0xFF, 0xFF, 0xFF, 0xFF}, 6);
        esp_now_add_peer(&peer);
        
        ESP_LOGI(TAG, "ESP-NOW initialized (channel %d)", ap_info.primary);
    } else {
        ESP_LOGE(TAG, "Failed to get AP info, using default channel 1");
        
        // 降级方案：使用默认信道1
        esp_now_peer_info_t peer = {
            .channel = 1,
            .ifidx = WIFI_IF_STA,
            .encrypt = false,
        };
        memcpy(peer.peer_addr, (uint8_t[]){0xFF, 0xFF, 0xFF, 0xFF, 0xFF, 0xFF}, 6);
        esp_now_add_peer(&peer);
        
        ESP_LOGI(TAG, "ESP-NOW initialized (channel 1)");
    }
    
    return true;
}
```

#### 常见问题与解决方案

**问题1：路由器信道动态变化**
```

```

**问题2：多个路由器**
```

解决：确保连接到同一个路由器
```

**问题3：信道范围**
```

解决：检查ap_info.channel是否合法，使用默认信道1作为降级方案
```

#### 总结

**ESP-NOW通信的三大前提**：
1. ✅ 同一个WiFi网络（同一个路由器）
2. ✅ 同一个WiFi信道（Channel必须相同）
3. ✅ ESP-NOW初始化成功（无错误）

- 主机和从机都使用`esp_wifi_sta_get_ap_info()`动态获取信道

- 打印日志确认信道一致

**调试技巧**：

- 搜索设备前确认信道一致
- 使用串口监视器对比主机和从机日志

## 第五章：WebSocket协议

### 5.1 WebSocket协议基础

WebSocket是一种**全双工通信协议**，在单个TCP连接上提供实时双向通信。

#### 协议特点

| 特性 | 说明 |
|------|------|
| **全双工** | 客户端和服务器可以同时发送数据 |
| **低开销** | 相比HTTP轮询，减少头部开销 |
| **实时性** | 服务器可以主动推送数据 |
| **持久连接** | 连接建立后无需重复握手 |

#### 握手过程

```
客户端（浏览器）                    服务器（小智ESP32）
     │                              │
     │ 1. HTTP GET /stream          │
     ├───────────────────────────────────►
     │                              │
     │ 2. 升级为WebSocket          │
     │                              │
     │ 3. 发送握手帧               │
     ├───────────────────────────────────►
     │                              │
     │ 4. 验证Sec-WebSocket-Key    │
     │                              │
     │ 5. 返回101 Switching Protocols │
     ├───────────────────────────────────►
     │                              │
     └── WebSocket连接建立 ◄───────────────
                                    │
                                    └── 开始双向通信
```

#### 握手帧格式

```http

Sec-WebSocket-Key: dGhlIHNhbXBs6sbSEcEG+4=

```

**响应**：

### 5.2 数据帧格式

WebSocket数据帧格式：

```
 0                   1                   2                   3
 7 6 5 4 3 2 1 0 9 8 7 6 5 4 3 2 1 0
├─┴─┬─┴─┬─┴─┬─┴─┬─┴─┬─┴─┬─┴─┬─┴─┐
│FIN│RSV│RSV│RSV│ OPCODE│ MASK│     Payload Length (7 bits)    │
├─┴─┬─┴─┬─┴─┬─┴─┬─┴─┬─┴─┬─┴─┬─┴─┤
│   │   │   │   │       │       │                         │
└─┬─┴─┬─┴─┬─┴─┬─┴─┬─┴─┬─┴─┬─┴─┬─┴─┘
  │   │   │   │   │       │       │
  │   │   │   │   │       │       └── Payload Length (7 bits)
  │   │   │   │   │       │           0-125: 实际长度
  │   │   │   │   │       │           126: 后续2字节表示长度
  │   │   │   │   │       │           127: 后续8字节表示长度
  │   │   │   │   │       │
  │   │   │   │   │       └── MASK (1 bit)
  │   │   │   │   │           0: 无掩码（服务器→客户端）
  │   │   │   │   │           1: 有掩码（客户端→服务器）
  │   │   │   │   │
  │   │   │   │   └── OPCODE (4 bits)
  │   │   │   │       0x0: 连续帧
  │   │   │   │       0x1: 文本帧
  │   │   │   │       0x2: 二进制帧
  │   │   │   │       0x8: 关闭帧
  │   │   │   │       0x9: Ping帧
  │   │   │   │       0xA: Pong帧
  │   │   │   │
  │   │   │   └── RSV (3 bits, 保留)
  │   │   │
  │   │   └── RSV (3 bits, 保留)
  │   │
  │   └── RSV (3 bits, 保留)
  │
  └── FIN (1 bit)
      0: 后续还有帧
      1: 最后一帧
```

#### 帧类型（OPCODE）

| OPCODE | 说明 |
|--------|------|
| 0x0 | 连续帧（分片传输） |

| 0x8 | 关闭帧（连接关闭） |

### 5.3 小智项目中的WebSocket应用

小智使用WebSocket实现**实时图传**功能，将摄像头画面推送到浏览器。

#### 服务器端实现

```c
// websocket_protocol.cc
class WebSocketProtocol {
public:
    // 发送二进制数据（摄像头图像）
    void SendBinary(const uint8_t* data, size_t len) {
        // 构建WebSocket帧
        uint8_t frame[10 + len];
        size_t frame_len = 0;
        
        // FIN=1, OPCODE=0x2（二进制帧）
        frame[0] = 0x82;
        frame_len = 1;
        
        // Payload Length
        if (len <= 125) {
            frame[1] = len;
            frame_len = 2;
        } else if (len <= 65535) {
            frame[1] = 126;
            frame[2] = (len >> 8) & 0xFF;
            frame[3] = len & 0xFF;
            frame_len = 4;
        } else {
            frame[1] = 127;
            // 8字节长度
            frame_len = 10;
        }
        
        // 复制数据
        memcpy(&frame[frame_len], data, len);
        frame_len += len;
        
        // 发送帧
        send(client_fd_, frame, frame_len, 0);
    }
    
    // 发送文本数据（控制指令）
    void SendText(const char* text) {
        // 构建WebSocket帧
        uint8_t frame[10 + strlen(text)];
        size_t frame_len = 0;
        
        // FIN=1, OPCODE=0x1（文本帧）
        frame[0] = 0x81;
        frame_len = 1;
        
        // Payload Length
        size_t len = strlen(text);
        if (len <= 125) {
            frame[1] = len;
            frame_len = 2;
        } else if (len <= 65535) {
            frame[1] = 126;
            frame[2] = (len >> 8) & 0xFF;
            frame[3] = len & 0xFF;
            frame_len = 4;
        } else {
            frame[1] = 127;
            frame_len = 10;
        }
        
        // 复制数据
        memcpy(&frame[frame_len], text, len);
        frame_len += len;
        
        // 发送帧
        send(client_fd_, frame, frame_len, 0);
    }
};
```

## 第七章：I2C通信

### 7.1 I2C协议基础

I2C（Inter-Integrated Circuit）是一种**两线制串行通信协议**，用于连接低速外设。

#### I2C总线

```
┌─────────────────────────────────────────────┐
│              ESP32主控                     │
│  ┌─────────┐    ┌─────────┐               │
│  │  SDA   │────│  SCL   │               │
│  └─────────┘    └─────────┘               │
└─────────────────────────────────────────────┘
        │               │
        ├───────────────┤
        │               │
   ┌────┴────┐    ┌────┴────┐
   │  OLED   │    │ MPU6050 │
   │ 0x3C    │    │  0x68   │
   └─────────┘    └─────────┘
```

**信号线**：
- **SDA**（Serial Data）：数据线（双向）
- **SCL**（Serial Clock）：时钟线（主机输出）

#### I2C时序

```
START → 地址 → ACK → 数据 → ACK → STOP
  │       │      │      │      │
  ↓       ↓      ↓      ↓      ↓
  └───────┴──────┴──────┴──────┘
```

**时序说明**：
- **START**：主机拉低SDA，然后拉低SCL
- **地址**：发送7位设备地址 + 1位读写位
- **ACK**：从机拉低SDA表示确认
- **数据**：发送8位数据
- **STOP**：主机拉高SCL，然后拉高SDA

---

### 7.2 ESP-IDF 5.x I2C API

#### 初始化I2C总线

```c
// 创建I2C总线
i2c_master_bus_config_t bus_config = {
    .i2c_scl_io_num = GPIO_NUM_14,      // SCL引脚
    .i2c_sda_io_num = GPIO_NUM_15,      // SDA引脚
    .clk_source = I2C_CLK_SRC_DEFAULT,  // 时钟源
    .glitch_ignore_cnt = 7,             // 毛刺过滤
    .flags.enable_pullup = true,         // 启用上拉电阻
};

ESP_ERROR_CHECK(i2c_new_master_bus(&bus_config, &bus_handle));
```

```c

    .scl_speed_hz = 400000,                 // 400kHz
};

// 添加设备到总线

```

#### 读写数据

- 设备地址必须不同（0x3C vs 0x68）
- 通信速度需一致（400kHz）
- 避免长时间占用总线

## 第八章：GPIO控制

### 8.1 GPIO基础

GPIO（General Purpose Input/Output）是**通用输入输出引脚**，用于控制外部设备。

#### GPIO模式

| 模式 | 说明 |
|------|------|
| **输入** | 读取外部信号（按键、传感器） |
| **输出** | 控制外部设备（LED、继电器） |
| **开漏输出** | 用于I2C等总线 |
| **上拉/下拉** | 防止引脚悬空 |
